Лёгкая фоновая служба без внешних зависимостей и графический менеджер в стиле Windows 11 Fluent Dark для Windows 10/11 и Linux. Устраняет циклические сбросы драйвера в простое (`nvlddmkm Event ID 14 / 153`) и синие экраны `BSOD 0x0000010E` (`VIDEO_MEMORY_MANAGEMENT_INTERNAL`) на перепаянных и майнинговых видеокартах NVIDIA (`CMP 30HX / 40HX / 50HX / 70HX / 90HX / 170HX`, `P102 / P104 / P106`, перепаянных `16 GB / 20 GB / 22 GB` картах RTX/GTX).

## Причина проблемы

Видеокарты NVIDIA с перепаянной видеопамятью (например, 16 GB CMP 40HX, 20 GB RTX 3080, 22 GB RTX 2080 Ti) и часть майнинговых моделей стабильно работают под нагрузкой, но при переходе в простой снижают напряжение до минимальных P-состояний (~760 мВ). Поскольку нестандартные чипы/страпы GDDR6 или таблицы питания VBIOS не откалиброваны под такие просадки напряжения:

1. На патченых драйверах (`dartraiden/NVIDIA-patcher`) Windows начинает выдавать циклические сбросы WDDM TDR (`nvlddmkm Event ID 14` и `153`) каждые ~14-20 секунд в простое, вызывая фризы и обрыв CUDA/Vulkan контекстов.
2. При включённом анлоке вычислений и ReBAR (например, `Cyridd/cmpunlocker` для CMP 40HX) срабатывание TDR в простое напрямую приводит к синему экрану `BSOD 0x0000010E` (`VIDEO_MEMORY_MANAGEMENT_INTERNAL`).
3. Минимальный непрерывный вычислительный пульс удерживает GPU выше порога нестабильного напряжения в простое, почти не занимая VRAM и не мешая реальным задачам.

## Альтернативные решения и сравнение с NV-KeepAlive

Ещё одно рабочее решение на Windows — **фиксация напряжения/частоты видеокарты** в утилитах разгона, например в **EVGA Precision X1** (Boost Lock / фиксация напряжения) или **MSI Afterburner** (фиксация точки на кривой VF через `Ctrl+L`).

| Подход | Принцип работы | Плюсы и ограничения |
|---|---|---|
| **EVGA Precision X1 / MSI Afterburner (фиксация напряжения)** | Жёстко фиксирует напряжение/частоту на стабильной точке кривой VF, не давая карте сбрасывать вольтаж в простое. | Не занимает VRAM; просто настроить на обычном домашнем ПК. **Ограничения:** работает только в пользовательской GUI-сессии после входа в Windows (не защищает экран входа, перезагрузку и headless-сессии); требует постоянно запущенную стороннюю утилиту; не работает на Linux; на части CMP-карт и патченых драйверов управление кривой VF заблокировано. |
| **NV-KeepAlive (системная служба)** | Запускает микро-ядро с буфером 512 байт из Windows `Session 0 (SYSTEM)` или Linux `systemd` и полностью уступает карту через NVML при появлении реальной нагрузки. | Работает до входа в Windows, переживает выход пользователя, работает на Linux, поддерживает несколько видеокарт с разными движками, не требует сторонних рантаймов. **Ограничения:** занимает ~5-20 MiB VRAM в режиме Vulkan (или ~200-300 MiB в CUDA); температура в простое чуть выше глубокого сна P8. |

Если фиксация напряжения в EVGA Precision X1 или MSI Afterburner уже решает вашу задачу на Windows и защита до входа в систему / на Linux не требуется — это вполне рабочий вариант. NV-KeepAlive нужен там, где требуется системная фоновая защита до входа в ОС, Linux, мульти-GPU или отсутствие лишнего софта в трее.

## Архитектура: один бинарник с движками Vulkan и CUDA

Оба вычислительных движка встроены в **один и тот же исполняемый файл** (`NvKeepAlive.exe` на Windows, `nv-keepalive` на Linux). Скачивать отдельную CUDA-сборку не нужно; CUDA Toolkit и Vulkan SDK не требуются ни при сборке, ни при работе:

1. **Vulkan Compute (рекомендуется для большинства систем):**
   - Динамически загружает системную `vulkan-1.dll` (Windows) или `libvulkan.so.1` (Linux).
   - Собирает в памяти встроенный SPIR-V 1.0 шейдер (~350 байт, обычный FP32 FMA-цикл без `VK_NV_cooperative_matrix2`).
   - Выделяет буфер 512 байт; суммарный расход драйвера составляет **~5-20 MiB VRAM на карту**.
2. **CUDA Driver API (если в системе нет Vulkan или драйвер Vulkan нестабилен):**
   - Динамически загружает `nvcuda.dll` (Windows) или `libcuda.so.1` (Linux).
   - Загружает встроенный PTX 6.0 (`sm_50+`) через `cuModuleLoadData`.
   - Суммарный расход контекста CUDA составляет **~200-300 MiB VRAM на карту**.

Общие механизмы обоих движков:
- **Детектор внешней нагрузки через NVML (опрос раз в 250 мс):** читает `nvmlDeviceGetUtilizationRates` по PCI Bus ID конкретной карты. Как только внешняя задача (LLM, PyTorch/ComfyUI, игры, кодирование) нагружает контроллер памяти `>= 5%`, служба полностью прекращает отправку пакетов (`0.00%` CPU, без переключения контекстов Vulkan/CUDA) и мгновенно возвращается к защите после завершения задачи.
- **Сортировка по PCI Bus ID:** все видеокарты NVIDIA (`vendorID == 0x10DE`, карты AMD и Intel игнорируются) сортируются по PCI Bus ID (`VK_EXT_pci_bus_info`, `cuDeviceGetPCIBusId`, `nvmlDeviceGetHandleByPciBusId_v2`), благодаря чему индексы GPU на 100% совпадают с `nvidia-smi`.
- **Корректное завершение при выключении Windows:** обработчик Win32 `SetConsoleCtrlHandler` на `CTRL_SHUTDOWN_EVENT` с высшим приоритетом завершения (`SetProcessShutdownParameters(0x3FF, 0)`) освобождает GPU-контекст до выгрузки `dxgmms2`/`nvlddmkm`, исключая долгое выключение ПК и дампы `BSOD 0x10E (0x2D)` на выключении.
- **Чистый выход при отсутствии NVIDIA GPU (`--wait-timeout 30`):** ждёт до 30 секунд при загрузке ОС, и если видеокарты NVIDIA нет — завершается с кодом `0`.

## Установка и интерфейс на Windows

1. Скачайте и распакуйте **`NV-KeepAlive-Windows-v1.1.0.zip`** со страницы Releases.
2. Запустите **`NvKeepAliveUI.exe`** (~90 КБ, нативный WPF-интерфейс в стиле Windows 11 Fluent с автоподстройкой светлой/тёмной темы под Windows, без внешних зависимостей).
3. В окне программы:
   - В правом верхнем углу доступны переключатели языка (**RU / EN**) и темы (**Авто / Тёмная / Светлая**); в режиме Авто тема меняется на лету вслед за темой Windows.
   - Отображаются все видеокарты NVIDIA с живой телеметрией из `nvidia-smi` (`PCI Bus ID`, `PCIe`, общая VRAM, точная **VRAM самого фикса** из `GPU Process Memory`, температура, мощность), живая нагрузка `CPU%` и короткие счётчики сбоев `TDR (5 мин)` и `С запуска`.
   - Для каждой видеокарты явно выбирается движок **Vulkan** или **CUDA** (без скрытого `auto`). Если выбран Vulkan, но `vulkan-1.dll` или NVIDIA Vulkan ICD отсутствуют, открывается окно с диагностикой причины, пошаговым гайдом по установке (LunarG Vulkan Runtime / драйвер NVIDIA), кнопкой **Проверить снова** и быстрым переключением на CUDA.
   - Нажмите **Установить** (или **Переустановить** после изменения настроек) — служба `NvKeepAlive.exe` копируется в `%ProgramData%\NV-KeepAlive\` и регистрируется задача `NV-KeepAlive` (`SYSTEM`, `AtStartup` + `AtLogOn`).
   - Нажмите **Тест 25с** для проверки отсутствия ошибок `nvlddmkm` за 25 секунд.
   - Опционально (показывается только при выбранной CMP-карте): тумблер **`GGML_VK_DISABLE_COOPMAT2`** с отдельной кнопкой **Применить** (нужен только на стоковых CMP без EFI-анлока в `llama.cpp` / LM Studio; после анлока выключите).

## Установка на Linux

**Вариант A — Интерактивный терминальный менеджер (`nv-keepalive-tui`, рекомендуется):**
```bash
sudo bash nv-keepalive-tui
```
Терминальный TUI без внешних зависимостей (работает на десктопе, по SSH и в Live ISO): живая телеметрия `nvidia-smi`, выбор `Vulkan | CUDA` для каждой карты, живая VRAM фикса и `CPU%`, счётчик `NVRM: Xid`, встроенный гайд при отсутствии Vulkan, тест 25с и переключение языка RU/EN (`L`).

**Вариант B — Скрипт установки (`install-linux.sh`):**
```bash
sudo bash install-linux.sh
```

Скрипт установки:
1. Использует готовый бинарник `linux/bin/nv-keepalive-linux-x86_64`, если он совместим с системной libc, либо локально компилирует `linux/nv_keepalive.c` через `gcc` / `clang` (заголовки Vulkan/CUDA SDK не требуются).
2. Предлагает явный выбор движка (`[1] Vulkan` или `[2] CUDA`). Если выбран Vulkan, но `libvulkan.so.1` или NVIDIA Vulkan ICD отсутствуют, выводит команды установки для Debian/Ubuntu (`apt`), Arch (`pacman`) и Fedora/RHEL (`dnf`) с возможностью перепроверить или переключиться на CUDA.
3. При наличии нескольких видеокарт позволяет выбрать конкретные карты или назначить разные движки (`0:cuda,1:vulkan`).
4. Устанавливает и запускает `nv-keepalive.service` (`Restart=on-failure`).

Неинтерактивная установка:

```bash
sudo bash install-linux.sh --targets 0:vulkan
sudo bash install-linux.sh --targets 0:cuda,1:vulkan
```

Управление службой:

```bash
nv-keepalive --status
systemctl status nv-keepalive
sudo touch /run/nv-keepalive.pause   # пауза (освобождает GPU)
sudo rm -f /run/nv-keepalive.pause   # возобновить
sudo bash uninstall-linux.sh         # полное удаление
```

## Несколько видеокарт и разные движки для разных карт

Один процесс `NvKeepAlive` может одновременно обслуживать несколько видеокарт NVIDIA с разными движками на каждой карте:

```text
NvKeepAlive.exe --targets 0:cuda,1:vulkan --quiet --log "%ProgramData%\NV-KeepAlive\keepalive.log"
```

- Если в системе **одна** видеокарта NVIDIA, в `NvKeepAliveUI.exe` чекбокс скрыт и остаётся только переключатель `Vulkan | CUDA`.
- Если в системе **две и более** карт NVIDIA (например, `RTX 4070` + `CMP 40HX`), чекбоксами можно защитить только нужные карты, не затрагивая основную видеокарту.
- Все индексы отсортированы по PCI Bus ID и совпадают с порядком `nvidia-smi`.

## Синхронизация с PCIe Gen2 Unlock и фикс чипсетного моста (CMP 40HX)

`cmpunlocker` (`https://github.com/Cyridd/cmpunlocker`) — сторонний открытый проект конкретно для `NVIDIA CMP 40HX` (`DEV=0x1F0B`), который разблокирует полные FP16/Tensor Cores, 8 GiB Resizable BAR и PCIe Gen2. Сторонние бинарники и драйверы анлокера в `NV-KeepAlive` **не встраиваются**.

Когда в `NvKeepAliveUI.exe` выбрана `CMP 40HX` (`DEV=0x1F0B`), появляется блок **Синхронизация с PCIe Gen2 Unlock** (кнопка `?` показывает статус анлокера в системе и открывает страницу релизов автора):

1. **Безопасная работа с EFI-анлоком:** удерживает `NvKeepAlive.exe` активным во время работы `40HXInstaller.exe -gen2`, чтобы PnP-фолбэк Windows не отключал EFI-разлоченную карту (`CPU-RM / GSP OFF`) и не вызывал BSOD `0x10E`; зависшие файлы паузы после аварийных перезагрузок автоматически удаляются при старте службы.
2. **Синхронизация задачи и пробуждение из сна:** кнопка **Синхронизировать** сохраняет бэкап оригинальной задачи `40HX PCIe Gen2 Bring-up` (`gen2-orig.xml`), оборачивает её в `%ProgramData%\NV-KeepAlive\gen2-sync-wrapper.cmd` (оригинальный `40HXInstaller.exe` -> `--retrain-gen2`) и добавляет триггер пробуждения из сна (`Power-Troubleshooter Event ID 1`). Кнопка **Отключить** полностью восстанавливает исходную задачу.
3. **Наш встроенный фикс чипсетного PCIe-моста (`--retrain-gen2`):** если `CMP 40HX` установлена во втором/нижнем слоте материнской платы за PCIe-свитчом чипсета (типично для B550/X570/Z690, где родительский мост находится не на Bus 0), `40HXInstaller` разблокирует лимит карты (`max=Gen2`), но линк часто остаётся на `Gen1`. Режим `--retrain-gen2` сканирует все шины `0..255` через уже установленный пользователем `WinRing0x64.sys` из `CMP40HX-Unlock`, находит родительский PCIe-мост (`HeaderType==1 && SecondaryBus==gpuBus`), выставляет `TLS=Gen2` и выполняет `Link Retrain` (`LNKCTL |= 0x20`). Если карта уже работает на Gen2, команда завершается без изменений.

## Сборка из исходников

### Windows (Visual Studio и .NET SDK не требуются)

Используется встроенный компилятор `.NET Framework 4` (`csc.exe`):

```cmd

```

## Решение проблем

**Vulkan выдаёт `NO_LOADER` или `NO_NVIDIA_ICD`:**
- Windows: установите официальный LunarG Vulkan Runtime (`https://vulkan.lunarg.com/sdk/home#windows`) или переустановите драйвер NVIDIA с включённым Vulkan (в NVCleanstall оставьте компонент Vulkan отмеченным).
- Linux: установите `libvulkan1` (Debian/Ubuntu), `vulkan-icd-loader` (Arch) или `vulkan-loader` (Fedora/RHEL) и проверьте наличие `/usr/share/vulkan/icd.d/nvidia_icd.json`.
- Либо выберите движок `CUDA` для нужных карт.

**Ошибки Vulkan в `llama.cpp` / LM Studio на стоковой CMP без EFI-анлока:**
- Включите тумблер `GGML_VK_DISABLE_COOPMAT2` в `NvKeepAliveUI.exe`, нажмите **Применить** и перезапустите LM Studio / `llama.cpp`.
- После EFI-анлока выключите этот параметр, чтобы работали Tensor Cores.

**В шапке `NvKeepAliveUI.exe` отображается `CPU: -`:**
- Запустите `NvKeepAliveUI.exe` с правами администратора (подтвердив UAC), чтобы Windows разрешила чтение счётчиков `TotalProcessorTime` у процесса службы `SYSTEM`.
